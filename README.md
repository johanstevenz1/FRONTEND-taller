# Microservices Monitoring System

This repository contains a Java 17 and Spring Boot application for an in-memory microservices monitoring system. Inventory, orders, and payments operations run through a logging proxy. The same application serves the metrics API and a server-rendered monitoring dashboard at `/`.

## Requirements

- Java 17 or newer
- Maven 3.9 or newer

## Run locally

```bash
cd backend
mvn clean verify
mvn spring-boot:run
```

The dashboard is available at `http://localhost:8080/`; the API listens on the same origin. The health endpoint is `GET /api/health`.

Example requests:

```bash
curl -X POST http://localhost:8080/api/services/inventory/checkStock -H "Content-Type: application/json" -d "{\"params\":[\"P-100\"]}"
curl http://localhost:8080/api/metrics/summary
curl -X POST http://localhost:8080/api/metrics/simulate-load
```

## Configuration

| Variable | Default | Purpose |
| --- | --- | --- |
| `PORT` | `8080` | HTTP port, including Railway's injected port |
| `CORS_ALLOWED_ORIGINS` | `http://localhost:5173` | Comma-separated allowed browser origins; `*` is supported |
| `PAYMENTS_FAILURE_RATE` | `0.10` | Simulated payment failure probability from 0 to 1 |

## Deploy to Railway

Deploy the `backend/` directory using its Dockerfile. The dashboard and API are served together, so no separate frontend deployment is required. Railway supplies `PORT` automatically. Set `CORS_ALLOWED_ORIGINS` only if browser clients on another origin need to call the API.

## Dashboard behavior

The Java-served dashboard refreshes every three seconds and includes service health cards, recent latency charts, log filters, pagination, expandable request and response details, and a load simulation action. Dashboard markup and chart SVG are generated by Java; the application contains no JavaScript or TypeScript frontend.
